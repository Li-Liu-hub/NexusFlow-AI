# Go 版并行部署记录（2026-10-24）

> 分支 `feat/go-rewrite` @ `afdd245`。**并行验证部署：Java 栈未做任何改动。**

## 部署形态

Go 版 `platform-backend`（P0+P1 全量）以独立容器接入现有 apnet 网络，
与 Java 版 `ap-backend`（7529）**同库并行**、不接 nginx、不注册 Nacos：

```
容器    ap-backend-go   （nginx:1.27-alpine 作运行时，entrypoint 覆盖）
二进制  /opt/agent-platform/go-backend/platform-backend  （CGO=0 静态，22MB）
网络    agent-platform_apnet；端口 :7529（容器内，与 Java 版互不冲突）
内存    --memory 128m（实际占用 3.2 MiB —— Java 版 244 MiB）
数据    直连 mysql:3306/api_db，账号复用 compose/.env 的 MYSQL_APP_USER/PW
```

启动命令（重放用）：

```bash
sudo bash -c 'set -a; . /opt/agent-platform/compose/.env; set +a; docker run -d \
  --name ap-backend-go --restart unless-stopped --network agent-platform_apnet --memory 128m \
  --entrypoint /app/platform-backend -v /opt/agent-platform/go-backend:/app:ro \
  -e HTTP_ADDR=:7529 \
  -e MYSQL_DSN="${MYSQL_APP_USER}:${MYSQL_APP_PW}@tcp(mysql:3306)/api_db?parseTime=true&loc=Local&charset=utf8mb4&timeout=5s" \
  -e GATEWAY_BASE_URL=http://gateway:8090 \
  -e DIGITAL_HUMAN_BASE_URL=http://digital-human:8126 \
  -e DIGITAL_HUMAN_GW_PREFIX=/digitalHuman/admin \
  nginx:1.27-alpine'
```

## 发现的遗留问题（Java 版同样存在，非 Go 回归）

- 验收 C2/C4 在**线上 Java 版本来就是 FAIL**（`/home/ubuntu/acc2.log` 有记录）：
  `user` 表 admin 的口令摘要对应 123456，但 `/user/login` 校验密码 ≥8 位，
  线上验收传入的 ACC_ADMIN_PW 与库内摘要不匹配 → C3/C4 的会话链路全挂。
  Go 版行为与 Java 逐字一致（`"用户不存在或密码错误"`）。
