## 三、本次踩过的坑（下次直接跳过）

| 坑 | 现象 | 解法 |
|---|---|---|
| sshd 的 sftp 子系统被注释 | paramiko `sftp.put` 报 ENOENT（连 `/home/ubuntu` 都开不了） | 用 `ssh_stdin_upload.py`（exec 通道 `cat > file` + md5 校验） |
| Git Bash 路径转换 | 远端路径 `/home/...` 被本地转成 `D:/WorkBuddy/.../PortableGit/home/...` | 所有 ssh 命令前加 `MSYS_NO_PATHCONV=1` |
| 清华 PyPI 镜像抽风 | `pip install uv`：`from versions: none` | Dockerfile 两个 index 改 `mirrors.aliyun.com/pypi/simple/` |
| SSH 通道 30 分钟超时 | 长构建被 paramiko PipeTimeout 断开 | `sudo setsid nohup bash build.sh > log 2>&1 < /dev/null &` + 轮询状态文件 |
| **orchestrator 的 env 来源** | 往 `/opt/app/orchestrator/.env` 加 `GRAPH_SOURCE` 无效 | 当前 compose 用 `environment:` 段注入（不是 env_file）——必须改 `compose/docker-compose.yml` |
| compose 变量被本地展开 | `sed 's|...:${TAG}|'` 在本地 bash 先把 `${TAG}` 展平成空 | 用行号定位 sed（`273s|...|`）或单引号包裹 |
| 容器 8125 不对外 | 宿主机 `curl 127.0.0.1:8125` 无响应（orchestrator 在 apnet，非 host 网络） | 容器内测：`docker exec ap-orchestrator ...` |
| 容器系统 python 无依赖 | `docker exec python script.py` → `No module named httpx` | 用 venv：`/app/.venv/bin/python` |
| buildkitd 续跑 | SSH 断开后构建仍在服务器后台继续（buildkit 守护进程接管） | 查 `docker images` + `/tmp/canvas-build.status` 判断真实状态 |
