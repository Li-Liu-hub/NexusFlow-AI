## 0. 为什么 `docker ps -a` 查不到？

**因为我没有用 Docker 部署。** 五个中间件全部是**原生服务**：

- 四个数据库/消息中间件用 `apt` 安装，由 **systemd** 托管（`systemctl status xxx` 可查）
- Nacos 是解压到 `/opt/nacos` 的独立 JAR，注册成一个名为 `nacos` 的 systemd 单元

这么做是为了对齐 `local-init/` 的思路（本机原生中间件），也省掉镜像拉取和内网穿透的麻烦。
如果你希望改成 Docker Compose 编排，说一声，我可以把这套原生化部署换成 compose（服务器上 Docker 是装好的，`sudo docker ps` 可用）。

## 4. ⚠️ 当前唯一未打通的一环：轻量应用服务器的「防火墙」

服务器**本机没有任何防火墙拦截**（`ufw` inactive；`iptables` 的 `YJ-FIREWALL-INPUT` 链只针对 22 端口做暴力破解封禁）。
但从你本机测试，除 22 外**所有端口都是超时（DROP）**——这是**腾讯云轻量应用服务器的防火墙**在云网络层丢弃。

### 实测取证（2026-09-30，可复现）

在服务器上临时插一条**只计数、不改变行为**的规则，看外部连接时计数涨不涨：

```bash
# ① 埋规则（pkts 从 0 开始）
sudo iptables -I INPUT 1 -p tcp -m multiport --dports 3306,5432 -j ACCEPT
sudo iptables -nvL INPUT --line-numbers | head -5
# ② 从外网发起连接（3306/5432 各 3 次，全部 TimeoutError）
# ③ 再读计数
sudo iptables -nvL INPUT --line-numbers | head -5
sudo iptables -D INPUT -p tcp -m multiport --dports 3306,5432 -j ACCEPT   # 清理
```

**结果**：

| 观测项 | 数值 | 含义 |
|---|---|---|
| 服务监听 | `3306 -> 0.0.0.0:3306`、`5432 -> 0.0.0.0:5432,[::]:5432` | 服务本身没问题 |
| `INPUT` 策略 | `ACCEPT`，`ufw` inactive | 主机防火墙不拦 |
| 外部连接 6 次 | 全部 `TimeoutError (4.01s)` | 超时 = 丢包，不是拒绝 |
| 计数规则 | **`pkts=0 bytes=0`** | **包根本没到达主机** |
| `YJ-FIREWALL-INPUT` 计数 | 从 53301 涨到 53789 | 计数机制正常，主机在正常收包 |

→ 拦截点确凿在**主机之外的云平台网络层**。判断口诀：**超时（DROP）= 上游云防火墙；拒绝（REJECT）= 本机规则**。

### ⚠️ 这台机器是「轻量应用服务器」，不是 CVM

- 实例 ID `lhins-efltpzqo8`，控制台 URL 形如 `console.cloud.tencent.com/lighthouse/instance/detail?...`
- **轻量应用服务器没有「安全组」，它用的是「防火墙」** —— 一套独立的放行白名单，
  默认只开 22 / 80 / 443 等少量端口，其余**全部丢弃**
- **别去 CVM 的安全组页面找这台机器，找不到**（两种产品的放行入口完全不互通）

> 判定产品类型：`curl -s http://metadata.tencentyun.com/latest/meta-data/instance-id`
> → `lhins-` 开头是轻量应用服务器（去「防火墙」），`ins-` 开头是 CVM（去「安全组」）。

### 放行操作

| 路径 | 走法 |
|---|---|
| A（最快） | 实例详情页「网络与域名」→ 点「**管理防火墙规则**」 |
| B | 轻量应用服务器 → 点进实例 → 上方页签「**防火墙**」→ 添加规则 |
| C | 左侧栏「轻量应用服务器 → **防火墙模板**」→ 建模板后套用到实例 |

每条规则填：应用类型 `自定义` / 协议 `TCP` / 端口见下表 / 来源 `0.0.0.0/0`。

> 来源**能填你自己的公网出口 IP 就别用 `0.0.0.0/0`**（查法：浏览器打开 `ip.sb`）。
> 如果出口 IP 是动态的，那只能 `0.0.0.0/0`，请务必只用于临时调试。

要放行的端口：

| 端口 | 协议 | 用途 | 是否必须 |
|---|---|---|---|
| `3306` | TCP | MySQL | 必须 |
| `5432` | TCP | PostgreSQL | 必须 |
| `6379` | TCP | Redis | 必须 |
| `5672` | TCP | RabbitMQ AMQP | 必须 |
| `15672` | TCP | RabbitMQ 管理台 | 建议 |
| `8848` | TCP | Nacos HTTP | 必须 |
| `9848` | TCP | Nacos gRPC（客户端） | 必须 |
| `9849` | TCP | Nacos gRPC（服务端） | 必须 |

**如果你打算把这套应用也部署到服务器上跑**（而不是本机连远程），那么这些端口一个都不用开——应用走 `localhost` 即可，更安全也更快。要开的话只开应用对外端口就行：`8000`（前端）、`7529`、`8090`、`8123`、`8124`、`8125`。

> 安全提醒：源 IP 建议限制为你自己的出口 IP 段，而不是 `0.0.0.0/0`。
> 当前这套密码（`root/123456`、`guest/guest`、Redis 无密码、Nacos 无鉴权）**对公网开放等于裸奔**，MySQL 和 Redis 是最常被扫的两个目标，通常几小时内就会被打。仅用于临时调试，用完请立刻收紧。
