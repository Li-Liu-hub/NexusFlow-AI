## 设计要点

1. **`terminal` 的 33 列与 Excel 逐列对应**（附录 A 的字段映射），不做裁剪 —— 后续报表/盘点都要用。
2. **`warehouse_code` 是关联键**：源数据里 `归属仓位` 是中文名（如"吉林省长春市分公司"），
   而 `仓位编码` 是 4 位码（如 `7A00`）。业务上按编码关联，名称只作展示。
3. **仓位表从 terminal 数据派生**，不单独录入：按 `一级/二级/三级/四级仓位 + 归属仓位 + 仓位编码`
   去重生成，层级由"哪一列有值"判定。
4. **日期列在源文件里是 Excel 序列号**（如 `46197.6017592593`），导入时必须按 1900 基准转换。
5. 所有金额用 `DECIMAL(12,4)`，不用 float —— 源数据是 `150.4000` 这种 4 位小数。

## 1. `warehouse` 仓位

```sql
CREATE TABLE IF NOT EXISTS `warehouse` (
  `warehouse_code` VARCHAR(32)  NOT NULL COMMENT '仓位编码（业务主键，源数据 7A00/7AZA 这类 4 位码）',
  `name`           VARCHAR(128) NOT NULL COMMENT '仓位名称（源数据"归属仓位"列）',
  `level`          TINYINT      NOT NULL COMMENT '层级：1=省 2=地市 3=区县 4=网格 5=智家(虚拟)',
  `parent_code`    VARCHAR(32)      NULL COMMENT '上级仓位编码',
  `province`       VARCHAR(64)      NULL COMMENT '省',
  `city`           VARCHAR(64)      NULL COMMENT '地市',
  `district`       VARCHAR(64)      NULL COMMENT '区县',
  `created_at`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`warehouse_code`),
  KEY `idx_warehouse_parent` (`parent_code`),
  KEY `idx_warehouse_level`  (`level`),
  KEY `idx_warehouse_name`   (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='仓位（四级仓储体系 + 智家虚拟五级）';
```

## 2. `terminal` 终端台账（33 列）

```sql
CREATE TABLE IF NOT EXISTS `terminal` (
  `serial_no`         VARCHAR(64)   NOT NULL COMMENT '终端串码（PK）',
  `big_type`          VARCHAR(64)       NULL COMMENT '终端大类（光猫/机顶盒/FTTR…）',
  `small_type`        VARCHAR(64)       NULL COMMENT '终端小类',
  `vendor`            VARCHAR(64)       NULL COMMENT '终端厂家',
  `model`             VARCHAR(128)      NULL COMMENT '终端型号',
  `material_code`     VARCHAR(64)       NULL COMMENT '物料编码',
  `material_name`     VARCHAR(256)      NULL COMMENT '物料名称',
  `purchase_no`       VARCHAR(128)      NULL COMMENT '采购单号',
  `terminal_status`   VARCHAR(32)   NOT NULL COMMENT '终端状态，见下方枚举',
  `inbound_type`      VARCHAR(32)       NULL COMMENT '入库类型（新终端…）',
  `business_type`     VARCHAR(32)       NULL COMMENT '业务类型',
  `purchase_type`     VARCHAR(32)       NULL COMMENT '采购类型（采购入库…）',
  `status_changed_at` DATETIME          NULL COMMENT '状态变更时间',
  `lv1_warehouse`     VARCHAR(128)      NULL COMMENT '一级仓位名（省公司）',
  `lv2_warehouse`     VARCHAR(128)      NULL COMMENT '二级仓位名（地市）',
  `lv3_warehouse`     VARCHAR(128)      NULL COMMENT '三级仓位名（区县）',
  `lv4_warehouse`     VARCHAR(128)      NULL COMMENT '四级仓位名（网格）',
  `owner_warehouse`   VARCHAR(128)      NULL COMMENT '归属仓位名',
  `warehouse_code`    VARCHAR(32)       NULL COMMENT '仓位编码（FK → warehouse.warehouse_code）',
  `target_warehouse`  VARCHAR(128)      NULL COMMENT '目标仓位',
  `unit_price`        DECIMAL(12,4)     NULL COMMENT '单价（元）',
  `customer_phone`    VARCHAR(64)       NULL COMMENT '客户号码',
  `receiver`          VARCHAR(64)       NULL COMMENT '领用人',
  `receiver_no`       VARCHAR(64)       NULL COMMENT '领用工号',
  `box_no`            VARCHAR(64)       NULL COMMENT '箱号',
  `first_inbound_at`  DATETIME          NULL COMMENT '首次入库时间',
  `aging_days`        INT               NULL COMMENT '库龄（天）',
  `warranty_start`    DATETIME          NULL COMMENT '保修起始时间',
  `warranty_end`      DATETIME          NULL COMMENT '保修结束时间',
  `operator`          VARCHAR(64)       NULL COMMENT '操作人',
  `operator_no`       VARCHAR(64)       NULL COMMENT '操作人工号',
  `second_inbound_at` DATETIME          NULL COMMENT '二次入库时间',
  `lost_compensation` DECIMAL(12,4)     NULL COMMENT '丢失赔偿价格',
  `created_at`        DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`        DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`serial_no`),
  KEY `idx_terminal_wh_status` (`warehouse_code`, `terminal_status`),
  KEY `idx_terminal_material`  (`material_code`),
  KEY `idx_terminal_model`     (`model`),
  KEY `idx_terminal_status`    (`terminal_status`),
  KEY `idx_terminal_aging`     (`aging_days`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='终端台账（串码级全生命周期）';
```

**`terminal_status` 枚举**（源数据实测 + 手册口径）：

| 值 | 说明 | 参与调拨 |
|---|---|---|
| `可用` | 可正常调拨/领用 | ✅ 调拨、下发 |
| `占用` | 已被占用 | ✕ |
| `在途` | 调拨中 | ✕（但计入"在途"口径） |
| `待检` | 待检测 | ✅ 收回、回退 |
| `待报废` | 待报废 | ✅ 收回、回退 |
| `待回收` | 待回收 | ✕ |
| `备机` | 备用机 | ✕ |
| `待智家领用确认` | 智家已领未确认 | ✕ |
| `领用退回` | 领用退回 | ✕ |

## 3. `transfer_order` 调拨单

```sql
CREATE TABLE IF NOT EXISTS `transfer_order` (
  `order_no`        VARCHAR(64)  NOT NULL COMMENT '调拨单号（业务主键）',
  `operation_type`  VARCHAR(16)  NOT NULL COMMENT '操作类型：TRANSFER 调拨 / ISSUE 下发 / RECALL 收回 / RETURN 回退',
  `from_warehouse`  VARCHAR(32)  NOT NULL COMMENT '调出仓位编码',
  `to_warehouse`    VARCHAR(32)  NOT NULL COMMENT '调入仓位编码',
  `status`          VARCHAR(16)  NOT NULL DEFAULT 'PENDING' COMMENT '状态：PENDING 待发起 / OUTBOUND 已出库 / DONE 已完成 / REJECTED 已拒绝',
  `item_count`      INT          NOT NULL DEFAULT 0 COMMENT '明细种类数',
  `total_quantity`  INT          NOT NULL DEFAULT 0 COMMENT '总数量',
  `need_approval`   TINYINT      NOT NULL DEFAULT 0 COMMENT '是否需要省级审批（跨本地网 + 仅单一物料）',
  `creator`         VARCHAR(64)      NULL COMMENT '创建人',
  `reject_reason`   VARCHAR(512)     NULL COMMENT '拒绝原因',
  `created_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `outbound_at`     DATETIME         NULL COMMENT '出库时间',
  `inbound_at`      DATETIME         NULL COMMENT '入库时间',
  PRIMARY KEY (`order_no`),
  KEY `idx_order_from`   (`from_warehouse`),
  KEY `idx_order_to`     (`to_warehouse`),
  KEY `idx_order_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='调拨单（含调拨/下发/收回/回退四种操作）';
```

```sql
CREATE TABLE IF NOT EXISTS `transfer_order_item` (

  `order_no`      VARCHAR(64)  NOT NULL COMMENT '调拨单号',
  `material_code` VARCHAR(64)  NOT NULL COMMENT '物料编码',
  `model`         VARCHAR(128)     NULL COMMENT '规格型号',
  `quantity`      INT          NOT NULL COMMENT '数量',
  `serial_nos`    JSON             NULL COMMENT '串码明细（出库时按单导入，用于型号/数量/状态三重校验）',
  `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_item_order`    (`order_no`),
  KEY `idx_item_material` (`material_code`)

```

## 5. `notice` 通知

```sql
CREATE TABLE IF NOT EXISTS `notice` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT,
  `receiver`    VARCHAR(64)  NOT NULL COMMENT '接收方（账号/工号/仓位）',
  `notice_type` VARCHAR(32)  NOT NULL COMMENT '类型：ORDER_CREATED / OUTBOUND / INBOUND / REJECTED / LOGISTICS',
  `title`       VARCHAR(128) NOT NULL,
  `content`     VARCHAR(1024)    NULL,
  `order_no`    VARCHAR(64)      NULL COMMENT '关联调拨单号',
  `is_read`     TINYINT      NOT NULL DEFAULT 0,
  `created_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_notice_receiver` (`receiver`, `is_read`),
  KEY `idx_notice_order`    (`order_no`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='站内通知';
```

## 业务硬规则（DDL 之外，Service 层必须校验）

来自 `开发文档.docx` 1.4 节 + 调拨规则截图：

| 规则 | 内容 | 落地位置 |
|---|---|---|
| 调拨四操作 | `TRANSFER` 上级发起调下属两个平级库；`ISSUE` 上级→下级不可跨级；`RECALL` 上级收回下级；`RETURN` 下级退上级。**四级账管仅支持 `RETURN`** | `TransferOrderService.validateOperation()` |
| 状态限制 | `TRANSFER`/`ISSUE` 仅允许源终端状态为 `可用`；`RECALL`/`RETURN` 允许 `可用`/`待检`/`待报废` | `TransferOrderService.validateStatus()` |
| 审批 | 四级库间调拨免审批；**跨本地网调拨需省级终端主管审批，且仅支持单一物料** | `need_approval` 字段 + 校验 |
| 闭环 | 用什么菜单建单，就在什么菜单入库确认；出库需按调拨单数量/型号导入串码 | `outbound`/`inbound` 端点 |
| **数字红线** | 所有库存数字必须来自「查数据库 + 固定算法」，**大模型不生成任何数字** | 编排层 `critic` 的数字 diff 闸门 |

### 清洗规则

1. **Excel 日期序列号** → `DATETIME`：`datetime(1899,12,30) + timedelta(days=serial)`
   （实测 `46197.6017592593` → `2026-06-17 14:26:32`）
2. `库龄`（第 27 列）若为浮点，四舍五入转 INT
3. `单价`/`丢失赔偿价格` 是字符串（`150.4000`）→ DECIMAL
4. 空字符串统一转 `NULL`（不用 `''`，否则会影响 `COUNT` 与索引）
5. 敏感列（客户号码/领用人/领用工号/操作人/操作人工号）导入时**原样入库**，
   但对外 API 与演示前端必须脱敏 —— 这是数据安全红线
