## 二、与原 README 不一致的地方（实测纠正）

| README 写的 | 实测真相 |
|---|---|
| aismp-agent 用 JDK 8 | **错**。`aismp-agent/pom.xml` 是 `spring-boot-starter-parent 3.5.16` + `<java.version>21</java.version>` + Spring AI 1.0.3，必须 **JDK 21** |
| 「构建全部模块」 | 根 `pom.xml` 只聚合 `aismp-backend` 和 `aismp-agent`；而 `aismp-backend/pom.xml` **没有 `<modules>`**，`aismp-common` / `aismp-client-sdk` / `aismp-gateway` / `aismp-interface` 各自继承 `spring-boot-starter-parent`（且版本各不相同：2.7.0 / 2.7.5 / 2.7.18）。必须逐个构建，且 common/sdk 要先 `install` |
| `ddl.sql` 建库 | 它建的是 `my_db`（含 `user`/`post`），而应用连的是 `api_db` |
| `db.sql` | 里面 `create table aismp.\`user_interface_info\`` 引用了不存在的 `aismp` 库（笔误）；且 20 条接口的 `requestParams` 为 NULL 而建表时该列是 `NOT NULL` |

1. **必须 `unset SERVER_PORT SERVER__PORT`**：本机进程环境里有 `SERVER__PORT=53176`，Spring Boot 会当成 `server.port` 把服务劫持走，配置文件里的端口完全不生效。

## 六、踩坑清单（本机特有）

1. **JDK 8 本机原本没有** —— 从清华 Adoptium 镜像下载 Temurin 8u504 解压到 `D:\env\jdk-8`。
2. **Redis 要密码** —— 本机 Redis 在 `D:\Office software\main file\Redis-x64-5.0.14.1`，`requirepass 123456`。
   不配的话网关鉴权**全线静默 403**（`getInvokeUser error` → `NOAUTH Authentication required`），
   现象是"签名明明对却一直 403"，极易误判成签名算法问题。
3. **`user` 表缺 `accessKey`/`secretKey`** —— 原 `ddl.sql` 没这两列，但 `User` 实体和网关都要用。
4. **网关按 `(path, method)` 精确查 `interface_info`** —— 只登记 `/api/name` 不够，
   真实请求是 `/api/name/get`，必须逐条登记，否则 403。
5. **MCP 的 `chat_memory` 表名** —— Spring AI 1.0.3 用的是 `SPRING_AI_CHAT_MEMORY`
   （`schema-postgresql.sql`），不是想当然的 `chat_memory`；且手工
   `JdbcChatMemoryRepository.builder()` **不会自动建表**（Builder 里没有 schema 初始化），必须自己建。
6. **llama.cpp 默认物理批 512 装不下 FAQ** —— 灌库报
   `input (539 tokens) is too large to process. increase the physical batch size`。
   启动参数必须加 `-b 2048 -ub 2048`。（默认 `n_ubatch=512`，`--embedding` 模式会强制 `n_batch=n_ubatch`）
7. **uv 的 venv 不能建在中文路径下** —— 项目路径含中文时，venv 里的 python 启动器读不到自己的
   `pyvenv.cfg`，报 `Cannot read 'D:\????\????\??\...'`，连 `--version` 都跑不了。
   解法：`UV_PROJECT_ENVIRONMENT=D:\env\venvs\agent-orchestrator` 把 venv 挪到纯 ASCII 路径。
8. **Nacos 2.1.0 下载** —— GitHub release 直连只有 100~150 KB/s 且会断流；
   用断点续传 `curl -C -` 才拉完（117MB）。华为云镜像路径已失效（返回 SPA 页面）。
9. **网关 `application.yml` 的 `dubbo.application.name` 与 backend 同名**
   （都是 `dubbo-springboot-demo-provider`，从示例里抄来的），目前不影响功能，但属于隐患。
10. **两个 llama-server 可以同时绑同一端口** —— 我第二次启动时误带旧参数，
    两个实例**都监听 8090**（Windows SO_REUSEADDR 行为），
    `netstat` 会显示两行相同端口、两个 PID。排查端口冲突时不能只看"有没有监听"。

## 七、前端 aismp-frontend-master（Ant Design Pro 6 beta + Umi Max）

**本机三个必须的处理，缺一不可**（都写在 `start-frontend.sh` 里）：

### 7.1 依赖要用国内镜像装
仓库**没有 `package-lock.json`**，走 npmjs 全量解析会卡死（实测 16 分钟、文件数
137960 后 20 秒零增长，`node_modules/.package-lock.json` 一直不生成）。
```bash
npm install --registry=https://registry.npmmirror.com --no-audit --no-fund   # 90 秒装完
```
另外 `postinstall` 的 `max setup` 会失败（原因见 7.3），但 `src/.umi` 由 `max dev`
自己生成，**postinstall 失败不影响启动**。

### 7.2 必须清掉 `NODE_OPTIONS`（WorkBuddy 注入的 safe-delete 守卫）
WorkBuddy 会往环境里注入
`NODE_OPTIONS=--require="D:/WorkBuddy/resources/app.asar.unpacked/cli/vendor/shim/node-language-shim.cjs"`，
其中含 safe-delete 守卫。`umi dev` 启动时要 `rimraf` 掉 `src/.umi` 临时目录，被守卫拦下：
```
fatal - Error: [safe-delete][SAFE_DELETE_BULK_GUARD_ERROR] state lock timeout
    at checkBulkDeleteGuard (node-safe-delete-shim.cjs:239:19)
    at rimrafSync (...)
    at Command.fn (preset-umi/dist/commands/dev/dev.js:76:27)
```
→ 启动前 `unset NODE_OPTIONS`。

### 7.3 ⭐ 最关键：esbuild 二进制必须挪到纯 ASCII 路径（奇安信拦中文路径）
现象——**每一次文件读取**都被拒：
```
X [ERROR] Cannot read file "package.json": winapi error #5
X [ERROR] Cannot read file "tsconfig.json": winapi error #5
X [ERROR] Cannot read file "src/.umi/umi.ts": winapi error #5
```
`winapi error #5` = `ERROR_ACCESS_DENIED`。

**定位过程（结论反直觉，别照直觉排查）**：
| 试验 | 结果 |
|---|---|
| node 自己的 `fs.readFileSync('package.json')` | ✅ 正常 → 不是文件权限问题 |
| esbuild **cwd 在 ASCII 路径**，但二进制在中文路径 | ❌ 仍失败 |
| esbuild **cwd 在中文路径**，但二进制在 ASCII 路径（`D:\env\esbuild\`） | ✅ 成功 |

→ **只看二进制所在路径，与 cwd 无关。** 本机装了奇安信天擎，它会拦截位于
含中文路径下的 `esbuild.exe`（与它拦 Docker / RabbitMQ `AppData` WAL 同一类行为）。

解法（`start-frontend.sh` 已内置）：
```bash
cp node_modules/@esbuild/win32-x64/esbuild.exe D:/env/esbuild/esbuild.exe   # 必须是同一份，版本要对上
export ESBUILD_BINARY_PATH="D:/env/esbuild/esbuild.exe"
```

### 7.4 启动与对接
```bash
./start-frontend.sh          # 8000，/api/ 代理到 http://localhost:7529（不走网关）
```
`config/proxy.ts` 里 `dev` 的 `/api/` target 是 `http://localhost:7529`，
即**前端直连 backend，不经过网关**（所以前端页面里的请求不需要 AK/SK 签名）。

验证：`curl http://127.0.0.1:8000/` → 200（umi shell），
`curl http://127.0.0.1:8000/umi.js` → 200、291596 bytes（webpack bundle 编译成功）。

## 八、⚠️ 仓库里有一份未完成的 Spring AI 2.0 迁移（与本次部署冲突）

**这不是我做的**，是另一个会话在并行改同一个仓库。发现问题时的状态：

| 文件 | 状态 |
|---|---|
| `aismp-agent/pom.xml` | 已被改为 `spring-boot-starter-parent **4.0.7**` + `spring-ai.version **2.0.0**` |
| `OaVectorStoreConfig.java` | 已按 2.0 重写（`OpenAiEmbeddingOptions.builder().baseUrl(...)` + `OpenAiEmbeddingModel.builder()`），并**保留了我加的 8099/bge-m3** |
| `application.yml` | 已按 2.0 扁平化（`options.model` → `model`） |
| `ToolCallAgent.java` / `SelectiveMemoryAdvisor.java` | **未改**，仍用 1.0 API |

编译失败的 4 个错误（停在 11:34，之后 2 小时无动静）：
```
symbol: variable DEFAULT_CONVERSATION_ID     → ChatMemory（2.0 只保留 CONVERSATION_ID）
symbol: method internalToolExecutionEnabled(boolean)  ×2
       → ToolCallingChatOptions.Builder（2.0 已彻底移除该方法）
```

**为什么我没有替它改完**：`internalToolExecutionEnabled` 在 2.0 里不是改名，而是
**被整块移除**，改由 `ToolExecutionEligibilityChecker` / `DefaultToolCallingManager`
策略接管。而 `ToolCallAgent` 是项目自研的 ReAct 四层循环，**必须让 Spring AI 不要
在内部执行工具**（否则和自研循环重复执行）。这属于「用 2.0 的新策略重新表达这个语义」
的设计决策，硬改成编译通过很可能做出**行为错误**的版本。

**我的处置（非破坏性）**：
1. 先把被我一并回滚的 `pom.xml` **原样还原**（有 md5 校验，确认没覆盖他们更新的版本）；
2. 不再碰他们的任何文件；
3. 用 `git archive HEAD` 把 **HEAD 的 1.0.3 源码**导出到 ASCII 路径
   `D:\env\builds\agent-103`，在那份副本上打本机适配（MiMo + 8099 + 小模型名），
   单独构建出可用的 jar；
4. `start-services.sh agent` 改成 **仓库 jar 优先、缺失时回退到隔离构建**，
   并打印醒目提示。

> 迁移完成后：直接 `cd aismp-agent && mvn clean package`，仓库产物会自动被优先使用，
> 然后删掉 `D:\env\builds\agent-103` 即可。

## 九、遗留与未做

- **智谱 Key 未接入**：本机用 MiMo 替代，语义上等价（都是 OpenAI 兼容端点），
  但 `glm-4-flash` 这类"专用小模型"的调用在 MiMo 上用的同一个大模型，成本/时延特征与线上不同。
- **业务表数据是造的**：`base_user`/`tm_order_track` 等 7 张表的 DDL 与数据为反推补全，
  仅够跑通工具调用；真实数据仍在原阿里云 RDS。
- **MCP `tools/call` 无用户身份**：MCP 通道不带 `X-User-Id`，`queryMyPermission`
  会返回「未找到您的用户信息」。这是设计使然（MCP 走标准协议头，没有 OA 身份上下文）。
- **`aismp-agent` 跑的是隔离的 1.0.3 构建**（见第 8 节），与仓库源码不同步。
